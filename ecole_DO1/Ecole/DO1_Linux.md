## Part 3. Настройка сети ОС.
- Установка хостнейма: 'sudo hostnamectl set-hostname user-1'
- Установка временной зоны: 'sudo dpkg-reconfigure tzdata'. Выбираем 'Europe/Moscow' либо 'Etc/GMT-3'.
- Названия сетевых интерфейсов: 'ip a'
- lo (loopback) это интерфейс в системе для обмена данными внутри одной системы (не выходя в сеть). Нужен для работы сервисов на самом хосте и обмена данными между ними через стек TCP/IP (например, чтобы база данных могла передавать данные на веб сервер, который в свою очередь уже будет связан с внешним интернетом через другой интерфейс, например eth0 или enp1s0)
- Для получения ip через DHCP прописываем команду 'sudo dhclient -v'. Чтобы узнать ip и gw используем команду 'ip r'. В нашем случае шлюз по-умолчанию это 192.168.100.1. а внешний ip сервера это 192.168.100.142:
![a924c649a502f9f34500489a60c31f08.png](../_resources/a924c649a502f9f34500489a60c31f08.png)
- Сбрасываем полученный по DHCP айпишник командой 'sudo dhclient -r'
- Для конфигурации статического ip на сервере можно использовать множество разных способов, в завимимости от дистрибутива, способа установки и тд. Я буду просто редактировать конфигурационный файл /etc/netplan/*.yaml с помощью текстового редактора vi. Мануал по конфигурации netplan можно посмотреть прямо на системе даже без интернет соединения, вызвав его командой 'man netplan Изначально установщик убунту автоматически прописал в netplan под названием интерфейса dhcp4: true. Удаляем это из конфигурации и вместо этого прописываем параметры addresses, gateway4 (для ipv4) и nameservers: addresses: (адреса dns серверов также для ipv4). затем применяем новую конфигурацию с помощью команды 'sudo netplan apply'
![0752e11f77b2e547787e4cc1ce756a77.png](../_resources/0752e11f77b2e547787e4cc1ce756a77.png)
Видим, что наш айпи адрес поменялся: ![1e5480ef5cf6ae4496ea212e06f01f65.png](../_resources/1e5480ef5cf6ae4496ea212e06f01f65.png)
- Из-за того, что конфигурацию интерфейса мы прописали непосредственно в файл /etc/netplan/*.yaml, а никакие другие сервисы не настраивают для нас интерфейсы автоматически, то при перезагрузке наши настройки остаются и мы можем пинговать ya.ru и 1.1.1.1:![128d7772e681f7c0b0a4c5cddcb641a2.png](../_resources/128d7772e681f7c0b0a4c5cddcb641a2.png)

## Part 8. Установка и базовая настройка сервиса SSHD.
- sudo apt install openssh-server; sudo systemctl enable sshd.service; sudo vi /etc/ssh/sshd.config (раскоментировать строчку Port и заменить 22 на 2022), чтобы порт поменялся sudo systemctl restart sshd.service && sudo systemctl daemon-reload.
- 'ps -C sshd' покажет PID процесса с названием sshd, если он активен (ps - команда показываюшая активные процессы. -С опция для выбора по имени команды. sshd название команды сервиса sshd.service)
- Вывод команды netstat -tan
![c34819ee13893e107f05157f7bc55490.png](../_resources/c34819ee13893e107f05157f7bc55490.png)
- Значения флагов: -t только tcp соединения; -a показать все сокеты веб-серверов (по дефолу показывает только с активным подключением); -n не показывать символьные имена хостов.
- Значения столбцов:
   1. протокол
   2. Recv-Q (receive queue) — очередь полученных данных, которые уже дошли до сокета, но ещё не прочитаны приложением.
   3. Send-Q (send queue) — очередь отправляемых данных, которые приложение записало в сокет, но ядро ещё не передало по сети.
   4. Local address — Внутренний (локальный айпи адрес) сервера
   5. Foreign address — Айпи адрес удаленного узла, в данном случае в выводе команды можно увидеть адрес 213.180.204.183:80 - это адрес сервера репозитория пакетов Убунту. Так как буквально секунду назад я скачивал программу netstat через http репозиторий, соединение еще активно, но в статусе закрытия (TIME_WAIT).
   6. State — статус соединения. LISTEN - узел активен и ожидает соединения.

- 0.0.0.0 это то же самое, что '*', а именно wildcard значение, обозначающее - "все сетевые интерфейсы на этом хосте", то есть и внутренний (localhost / 127.0.0.1) и любой внешний (интерфейс с айпи полученным например от провайдера или роутера)
